# 0.7.1 悬浮条置顶恢复

用户反馈悬浮条有时会被普通应用窗口挡住，可能在运行一段时间后发生。此前的普通窗口和 Edge 最大化切换检查未复现自然触发；检查当时运行的 0.7.0 实例时，横条的 Windows 置顶标志仍有效，尚未确定用户遇到现象的触发原因。

针对已验证的恢复缺口，横条可见时每 2 秒检查一次原生置顶标志，仅在标志丢失时重新设置；不激活窗口，也不显示手动或全屏隐藏的横条。没有对其他置顶窗口反复争抢前后顺序。

## 验证

- Windows 原生隔离测试 `npm run test:topmost`：先确认横条位于普通窗口上方，再通过 `SetWindowPos(HWND_BOTTOM)` 模拟外部移除置顶标志并降低层级，确认横条被普通窗口遮挡；修改后恢复置顶和实际遮挡关系，前台焦点未改变。修复前以 `HWND_NOTOPMOST` 注入相同现象，连续两次未自行恢复；注入为模拟，不能据此认定真实原因。
- 0.7.1 便携包暂存程序通过相同置顶恢复和焦点检查。
- 构建通过；自动测试在允许本地回环连接和临时文件操作的环境中 66 项通过、5 项跳过。
- 全屏原生检查的证据报告 13 项有结果的观察通过，包括普通最大化、全屏自动隐藏、退出恢复及手动隐藏；检查脚本进程退出码非零，因此该命令整体未通过，不能将其记为完整通过。当前为单显示器，物理多屏未测。
- 实际长时间运行、用户原有遮挡触发条件，以及与其他置顶窗口竞争的场景尚未复现或验证。
