# 0.12.3：拖动尺寸累积修复

在本机 scaleFactor=1.8374998569488525 的 Windows 环境复现：连续调用 setPosition 120 次，原 451×60 的窗口变为 619×186。实际悬浮条 IPC 路径也复现 452×62 → 614×159。

原因：移动时使用的 Electron setPosition 路径反复读取和设置经过 DPI 取整的原生窗口尺寸，误差不断累积。

修复：每次移动使用 setBounds 明确提供由当前配置、目标显示器可用宽度计算的尺寸；不把 getBounds 返回的尺寸作为下一次移动的输入。窗口起点仅用于计算位置。

验证：实际 Electron 悬浮条通过连续 120 次移动、30 次独立拖动的尺寸回归检查，同时保留指针释放、不可聚焦、分页、市场筛选等验证。最小诊断脚本保留在 artifacts/debug/drag-dpi-probe.cjs；物理多显示器跨屏未重复实测。

按照用户要求，此次仅构建和验证，不生成发布压缩包。
