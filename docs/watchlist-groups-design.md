# 自选分组设计

状态：已撤回。此文保留 0.10.0–0.10.1 的历史设计；2026-11-01 用户认为功能不实用，明确要求移除。0.11.0 起恢复单一自选列表，迁移与验证见[移除分组记录](./remove-watchlist-groups-validation.md)。

## 方案概览

2026-11-01 后续修订：用户指出分组按钮占用过多横向空间，0.10.1 将默认字号的按钮宽度从 80 减至 44 个逻辑像素，按两字组名预留空间；全部自选按钮简写为“全部”，标题和菜单继续使用完整名称。固定宽度、长名省略及分页共同计算的规则保持有效，见[验证记录](./compact-group-selector-validation.md)。

一份总自选清单，配合不可删除的“全部自选”视图和用户手动创建的单层分组。证券可以属于多个组；每个视图分别保存成员顺序和悬浮条展示勾选。设置页、悬浮条和面板共用当前视图：面板展示全部成员，悬浮条展示其中勾选的成员。

悬浮条通过固定宽度的组名按钮切组，设置页负责分组与成员管理。所有组相关修改自动保存，成功后统一生效；切组不改变总自选行情更新范围，不改变窗口原有显示意图。旧配置原样迁入全部自选视图，重启恢复上次选择的视图并从第一页开始。

## 已确认范围（第一轮）

- Q1：分组用于切换行情悬浮条当前关注的证券范围，支持不同关注场景之间的切换。
- Q2：同一只证券可以同时属于多个自选分组；它仍是总自选列表中的同一只证券，不为每个分组创建独立证券副本。
- Q3：第一版由用户手动创建、命名和调整成员，采用单层分组，不包含自动分类或嵌套分组。

术语见根目录 [GLOSSARY.md](../GLOSSARY.md)，成员关系取舍见 [ADR 0007](./adr/0007-overlapping-watchlist-groups.md)。

## 已确认展示与入口（第二轮）

- Q4：各个自选分组分别保存“显示在悬浮条”的勾选。同一证券在一个组勾选，在另一个组不勾选，互不影响。
- Q5：各组独立保存证券的拖拽排序，调整一个组不会改变其他组的顺序。
- Q6：自选行情面板跟随当前自选视图，展示该视图全部成员；悬浮条仅展示其中勾选的成员，再按现有规则分页。
- Q7：保留固定、不可删除的“全部自选”入口，汇集所有自选证券，也能找到尚未加入任何自定义组的证券。
- Q8：悬浮条展示紧凑的当前组名，点击菜单选择分组；创建、改名和成员管理放在设置页。第一版通过鼠标切组，不增加切组全局快捷键。

“全部自选视图”和“当前自选视图”已补入术语表；面板的定义按 Q6 更新。0.10.0 面板已按当前视图筛选。

## 已确认操作与恢复规则（第三轮）

- Q9：全部自选视图同样拥有独立的展示勾选和排序。升级时将原有自选顺序和勾选原样迁入全部自选视图，升级后默认打开全部自选，由用户自行创建其他组。
- Q10：设置页、悬浮条和面板共用一个当前自选视图。在设置中切换管理组，同步切换悬浮条和面板的展示范围。
- Q11：自定义组管理中支持从已有自选勾选加入，也支持搜索新证券加入。添加新证券时，同时加入总自选和该组；已有自选只增加成员关系。新加入的成员追加到该组末尾，默认不勾选悬浮条展示。
- Q12：在自定义组执行“移出本组”，仅取消当前组归属，保留总自选和其他组；在全部自选中执行“移除自选”，确认后从总自选及所有组中移除。删除分组需要确认，只删除分组和成员关系，保留证券；删除当前组后切回全部自选。
- Q13：切组后悬浮条回到第一页，面板滚动到顶部；重启恢复上次选择的视图，从第一页开始。空组保留当前选择并提示添加证券，有成员但无展示勾选时提示选择展示证券。每页数量及外观设置继续全局共用。
- Q14：新建组从空组开始，创建成功后进入该组管理。组名去除首尾空格，长度为 1–20 个字符，不能重名或使用“全部自选”。自定义组支持拖拽排序，全部自选固定最前；不设置应用内固定分组数量上限。
- Q15：全部自选持续更新行情，切组无需重新连接。切组、成员调整、展示勾选和排序立即自动保存，保存成功后统一生效；失败保留原状态并明确提示。

移出分组、移除自选、删除分组已分别补入术语表，三种操作的按钮名称和作用范围必须保持一致。

## 实现时必须保持的约束

- 总自选拥有证券身份和基础资料；每个视图拥有自己的展示选择和顺序。全部自选视图的成员等于总自选全集，不允许通过组成员操作使其漏掉已关注证券。
- 同一证券在总自选中只出现一次，在同一组中也只出现一次。已经属于某组的证券重复加入时，不重置该组已有的勾选或排列位置。
- 从一个组移出后再次加入，按新成员处理；不恢复已经取消的组内展示选择和原位置。移除自选后再次添加同样按新证券处理。
- 在自定义组搜索添加新证券时，总自选和该组的成员更新共同保存、生效，不能出现只加入一处却提示全部成功的中间结果。已有证券的总自选勾选和在其他组的展示选择保持原值。
- 切组、改名、调整组序和组内展示选择只影响视图，不改变行情订阅集合。真正增删总自选时，继续按现有行情服务边界更新订阅。
- 普通报价更新保持当前页和滚动位置；当前视图内的展示勾选、成员顺序及每页数量变化继续沿用原有回第一页的规则。修改其他组不改变当前视图的展示选择和成员顺序。
- 沿用现有按工作区宽度计算分页容量、末页不足不改变窗口宽度的规则；组名不能成为无限扩宽悬浮条的原因。
- 保留既有位置、外观、连接方式、受保护授权和快捷键选择；旧配置明确保存的全部取消勾选必须保留，不能因迁移重新全选。原 v1/v2 的兼容规则继续有效。
- 配置中的组和当前视图使用稳定身份，改名和重排不改变其身份；从合法的旧版本配置迁移与处理损坏的新版本配置应分别设计，不能把无法解析的分组数据当成新安装并静默覆盖原文件。
- 保存仍由主进程统一校验和串行提交；失败不广播成功状态，不留下只保存部分成员关系的结果。切组期间的添加操作绑定发起时的目标组，不能因异步查找结束时当前组已改变而加入另一组。
- 当前组缺失时的恢复、命名的比较方式、离线操作、面板展开状态及悬浮条空间分配按下方已确认 Q16–Q19 执行。

上述约束已由 0.10.0 的视图模型、串行候选配置提交及原生窗口检查落实；验证证据及未覆盖范围见验证记录。

## 已确认交互边界（第四轮）

以下边界已获用户确认，与前述规则共同构成完整设计：

- Q16：离线时允许创建、切换、改名、排序分组，修改展示勾选，以及把已有自选加入分组；全新证券继续连接后核验。搜索结果已在总自选但不在本组时，显示“加入本组”；已经在本组时显示“已在本组”，不重置任何既有状态。
- Q17：面板已经展开时，切组后保持展开、原位更新内容与尺寸，不重新打开或主动获取焦点。悬浮条被手动隐藏或因全屏隐藏时，在设置中切组仅保存选择，按既有可见性规则恢复后再展示新视图。面板入口统一为“查看行情／展开行情面板”，面板显示当前视图名称和该视图成员总数。
- Q18：悬浮条为当前组名预留固定宽度的选择按钮，保留连接状态圆点与独立拖动手柄；长名省略，菜单显示完整名称。按钮宽度随统一字体设置确定，不因组名长度改变；计入窗口宽度与分页计算，窄工作区继续减少实际每页证券数量。点击组名不应触发拖动，滚轮继续用于证券翻页。
- Q19：组名比较忽略首尾空格和英文字母大小写；“全部自选”为保留名称。若启动时保存的当前组已不存在，但其余配置有效，回到全部自选并明确提示，保留其余有效分组、展示选择和顺序；损坏的结构按配置错误处理，不静默删除分组或覆盖源文件。

## 实现结构

0.10.0 采用以下结构和保存边界：

- `watchlist` 继续作为证券身份及基础资料的唯一总清单；行情按完整 `symbol` 维护，视图不拥有独立行情副本。
- 全部自选视图与每个自定义组分别持有有序成员引用，每条引用包含 `symbol` 和该视图的展示勾选。全部自选的引用集合始终等于总清单全集；自定义组的成员必须属于总清单。
- 自定义组持有稳定 `id` 与可修改的 `name`，组数组表达拖拽顺序；全部自选使用固定身份，独立于可删改的自定义组数组。`activeViewId` 表达三个窗口共享的当前自选视图。
- 新配置结构升级为 v4：将旧 `watchlist` 的成员顺序和 `showInBar` 迁入全部自选视图，将证券资料保留在总清单；旧 v1/v2 先按现有兼容规则还原选择，再迁移。不保留一个同时影响所有组的第二套全局展示开关。
- 渲染时先按当前视图取得有序成员，再关联按证券身份维护的行情；悬浮条进一步过滤该视图勾选并分页，面板展示该视图所有成员。主进程的窗口宽度和面板行数必须使用同一份视图计算结果。
- 所有分组命令通过主进程集中验证，按命令顺序构造完整候选配置快照；候选快照写盘成功后才替换已提交状态并广播。不能先替换实时配置再等待写盘，否则后台行情广播可能提前泄漏未保存的视图状态。
- 跨窗口命令统一排序，避免一次失败回滚覆盖另一次成功修改。新增证券的查找结果与其目标视图绑定，目标组已被删除时明确失败，不改加到其他组。
- 复用既有行情连接与按总自选更新订阅的边界。只有改变总自选成员才走相应服务配置；分组操作不重建连接，也不丢失缓存行情或其他证券状态。
- 新增切组入口必须扩展现有受控桥接和发送者验证；创建、改名、成员管理等写操作继续限制在设置窗口。条内切组只拥有选择合法视图的权限。

以下为验收标准。配置和模型规则已通过自动化验证，焦点、窗口显示、工作区宽度和多窗口交互已有 Windows 原生窗口夹具证据；物理多屏和独占游戏全屏仍待真实环境验证，详见验证记录。

| 重复加入本组已有证券，或移出后重新加入 | 重复加入不重置已有位置和勾选；重新加入按新成员处理 | Q2、Q11 的身份与新成员规则 |
| 移出本组、在全部自选移除证券、删除分组 | 分别只取消本组归属、取消全部关注与归属、仅删除组并保留证券；删除当前组后进入全部自选 | Q12 |

| 当前组没有成员，或有成员但全部未勾选 | 保留当前组，分别提供添加成员或选择展示入口 | Q13 |
| 重启、迁移旧 v3 配置、迁移旧 v1/v2 配置 | 重启恢复当前组首页；旧数据迁入全部自选，保留原展示范围、顺序和其他设置 | Q9、Q13 及旧版本兼容规则 |
| 连续报价更新、分页末页不足一页 | 报价不重置页码或滚动位置；末页不因成员数量不足改变窗口宽度 | 原有分页行为及 Q13 |
| 切组或创建组时模拟写盘失败，期间仍有行情广播 | 所有窗口和重启配置仍为上次成功状态，明确提示失败，不短暂展示候选组 | Q15 |
| 从设置添加证券同时在横条切组，或目标组被删除 | 证券归入发起操作时的目标组；组被删除时操作失败，不加入错误组、不丢失其他成功修改 | Q10、Q11、Q15 的联合约束 |
| 离线管理、搜索结果中的已有证券加入组 | 本地分组操作可用，新证券维持连接后核验，按钮状态以本组归属判定 | Q16 |
| 面板展开、手动隐藏、全屏隐藏时分别切组 | 保持已有展开和显示意图，面板按当前视图原位更新 | Q17 |
| 最长组名、不同字体和窄工作区、点击组名旁拖动手柄 | 长名可识别且不覆盖行情，宽度与分页一致，切组与拖动分别正确响应 | Q18 |
| 英文大小写重名、当前组失效、损坏的新配置 | 按命名规则判重；合法配置仅失去活动组时回全部自选并提示；损坏配置不被静默清空覆盖 | Q19 |

## 代码核查：设计时的 0.9.1 行为

- 当前仅有一份总自选列表，以完整市场前缀和证券代码识别、去重证券；每只证券有一个全局的“显示在悬浮条”勾选。
- 悬浮条按总自选顺序过滤勾选项，再分页展示；自选行情面板展示全部自选，不按勾选过滤。
- 自选排序只有一份；设置中的拖拽顺序同时用于悬浮条和面板。
- 云端和 OpenD 按总自选列表维护行情；调整展示勾选和顺序不会改变订阅证券集合。
- 现有配置为 v3。新增证券默认不展示；旧配置缺少展示勾选时迁移为展示，明确保存的空选择会被保留。
- 现有快捷键仅包含显示／隐藏悬浮条、展开／收起行情面板、上一页、下一页；尚无切组操作。

## 设计树闭合记录

已确定的基础：切换关注场景 → 手动单层分组 → 同一证券可加入多个分组。

第二轮已确定：展示勾选与成员顺序按组独立 → 悬浮条和面板关注范围一致 → 固定全部自选入口 → 鼠标切组、设置中管理。

第三轮已确定：原有配置迁入全部自选 → 三个窗口共用当前视图 → 成员新增默认不展示 → 三类移除操作区分作用范围 → 自动保存并恢复上次视图。

第四轮已确定：已有自选的分组管理可离线使用 → 切组保留窗口显示意图 → 固定宽度组名入口与分页共同计算 → 英文大小写判重、当前组失效时恢复全部自选。

Q1–Q19 已全部确认，没有剩余产品决策分支。用户随后授权实施，0.10.0 已实现；本文保留设计决策，实际验证结果以验证记录为准。
