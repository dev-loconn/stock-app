# Windows 11 股票行情悬浮条：第一版完整方案

状态：用户已确认完整方案及全部补充工程建议。已实现首个真实行情悬浮条，并验证持续报价、受保护密钥及自选的重启恢复。本文保留完整目标；当前实现范围见 [stock-bar-validation.md](./stock-bar-validation.md)，逐项验收见 [acceptance.md](./acceptance.md)。

当前已实现行情口径、连接恢复、横条、自选、设置、托盘、全屏自动隐藏和 Windows x64 ZIP 便携交付。原生全屏及全屏视频检查通过，手动隐藏优先；发布程序可恢复真实行情，隐藏期间继续更新。真实盘前盘后、具体币种和实时/延迟属性、物理多屏、独占游戏和自启仍待实测。详见 [0.2.0 验证记录](./fullscreen-release-validation.md)，不能将本次交付视为全部产品验收通过。

## 目标与边界

2026-11-01：用户认为分组不实用，0.11.0 已移除 0.10.x 的自选分组，恢复单一自选列表、证券排序和展示勾选。旧分组配置按全部自选迁移，并保留原文件备份；当前规则见 [ADR 0008](./adr/0008-return-to-single-watchlist.md)，验证见[移除分组记录](./remove-watchlist-groups-validation.md)。

2026-11-01：0.9.0 的全局快捷键方案及排除 F12 的修正已获最终确认，四项操作、改键、禁用、冲突及焦点规则见[全局快捷键设计](./global-shortcuts-design.md)，验证见[快捷键记录](./global-shortcuts-validation.md)。

供个人在使用其他应用工作时，快速查看港股、美股股票和 ETF 的价格及涨跌幅。第一版仅支持 Windows 11 x64，采用 Electron + React + TypeScript + Vite，行情优先通过本机富途 OpenD 接入。

第一版原始范围不包含交易下单、持仓管理、价格提醒、期权、美股夜盘、走势图、富途自选同步、全市场名称模糊搜索或自动更新。证券搜索已按下述确认方案实现；0.8.0 应用户要求增加美股夜盘行情，其余边界沿用。

## 悬浮条与交互

| 项目 | 已确认方案 |
| --- | --- |
| 外观 | 深色窄横条，默认每只证券 180 逻辑像素，总宽随数量和屏幕空间计算；可调整单只宽度、字号和透明度 |
| 内容 | 证券简称、最新价、涨跌幅百分比；价格使用原币，不做汇率换算 |
| 颜色 | 红涨、绿跌、平盘灰色；涨跌保留正负号 |
| 数量 | 0.7.0 起自选总数不设应用内固定上限；仅勾选项进入横条，默认每页最多 3 只，可在外观设置修改，空间不足时减少实际每页数量 |
| 连接状态 | 正常仅显示小圆点，异常在全局一处显示简短状态，悬停看详情 |
| 分页 | 鼠标滚轮手动翻页，显示页码；不自动滚动或翻页 |
| 窗口 | 始终置顶，可从空白处拖动；平时不抢键盘焦点 |
| 单击 | 不展开证券详情 |
| 悬停 | 显示代码、币种、实际报价时段、数据时间和涨跌计算基准；时间注明时区 |
| 右键 | 查看全部行情、自选管理、设置、隐藏、退出 |
| 语言与缩放 | 简体中文，适配 Windows 缩放及显示器变化 |

常驻横条不显示成交量、走势图或货币符号。管理和设置窗口由用户主动打开时允许获取焦点。

自选列表由程序独立维护，支持搜索候选及一次点击核验添加；无结果时可输入准确代码（例如 HK.00700、US.AAPL）核验并添加；支持删除、排序和保存。同一证券不重复添加。0.7.0 起取消原先最多 10 只的应用限制，增加逐行展示选择；完整规则见本页“悬浮条展示选择与数量设置”。

### 2026-10-24 证券搜索扩展（已确认并实现，真实目录接入待验证）

本节保留 0.4.0 当时的规则与验证范围。其中 10 只自选上限及“自选已满”行为在 0.7.0 由下文展示选择方案替代，历史通过记录不代表仍存在该限制。

状态：Q1–Q16 及完整方案已获用户最终确认，已在 0.4.0 实现。自动检查及原生协议夹具验证通过；真实 OpenD 目录核查遇到已保存连接的握手拒绝，实际目录数量、完整性及真实名称覆盖率尚待验证。结果与证据见 [证券搜索验证](./security-search-validation.md)。

#### 范围与证券身份（Q1、Q3、Q16）

- 在现有设置页的自选管理区域补充证券搜索，覆盖香港、美国市场的股票和 ETF，自选上限仍为 10 只。
- 以“市场＋完整证券代码”区分证券。例如 `HK.09988` 和 `US.BABA` 可同时加入自选，各占一个名额；同一代码对应的不同名称及别名合并为一条搜索结果，不重复添加。
- 搜索结果展示证券名称、所属市场和完整代码，每条结果提供“添加”按钮，不增加第二次确认。

#### 搜索与结果展示（Q2、Q6、Q8、Q9、Q14）

- 支持代码片段、中文名称、英文名称及名称的拼音首字母，不包含错别字纠正。
- 忽略输入首尾空格，证券代码和英文不区分大小写，中文简繁体等价；拼音首字母支持前缀及包含匹配。
- 默认同时搜索港美市场，提供“全部／港股／美股”筛选。
- 停止输入约 200 毫秒后自动更新结果；这是输入防抖安排，不等同于已验证的端到端耗时指标。
- 排序优先级为完整代码精确匹配、前缀匹配、包含匹配；每次最多展示 20 条，更多结果提示继续输入关键词。
- 支持方向键选择结果；回车仅添加明确选中的结果，中文输入法选字期间不触发添加。
- 空输入只展示搜索提示，不展示热门推荐或搜索历史；目录未就绪、加载失败与真正无匹配结果分别提示。

#### 名称资料及覆盖边界（Q4、Q5、Q12）

- 名称资料优先使用富途，允许补充其他公开的名称和别名资料；外部名称与已核实的完整证券代码关联，不能因同名而合并不同证券。具体补充资料来源及实际覆盖率在实现时核查。
- 四类输入按实际取得的名称和经核实的别名匹配；拼音首字母基于已有中文名称生成。不承诺每只证券都有完整中英文名称或所有俗称；缺失名称不编造，代码搜索及完整代码核验入口仍可用。
- `700`、`腾讯`、`騰訊`、`Tencent`、`tx` 找到 `HK.00700`，以及 `aapl` 找到 `US.AAPL`，作为已约定验收样例；示例通过不能代替全市场覆盖率核查。
- 输入联想使用可持久化的本地证券目录。已有本地目录时，OpenD 未连接也能搜索；首次没有目录时明确提示需要连接并加载。
- 行情继续通过现有 OpenD 获取；持久化的是证券搜索资料，报价仍不作为跨启动缓存。采用本地目录的原因见 [ADR 0004](./adr/0004-local-security-directory-search.md)。

#### 添加、后备入口与异常处理（Q3、Q7、Q11、Q13）

- 添加必须连接 OpenD 并通过证券身份核验；点击结果旁“添加”后完成核验及保存，无需再确认一次。断线时显示“连接后添加”，不自动排队添加。
- 核验失败时保留查询和结果并说明原因，不新增自选；身份核验通过但没有行情权限时仍可加入自选，随后显示“无权限”，沿用当前行为。
- 搜索无结果但用户提供完整代码（如 `HK.00700`）时，保留“核验并添加”后备入口；仍须通过相同的连接、身份和数量核验。
- 添加成功后保留关键词及搜索结果，将该条标为“已添加”，新证券追加到自选末尾。是否已添加以本应用的自选列表为准。
- 已添加的证券不可重复添加；达到 10 只后仍可搜索，其他结果的添加按钮显示“自选已满”。

#### 目录维护（Q10、Q15）

- 目录超过一天时，在连接可用后后台刷新，并提供手动刷新；刷新期间继续使用已有目录。
- 刷新失败时保留旧目录，显示更新时间与失败提示。
- 各市场独立维护可用目录及更新状态。例如港股刷新成功、美股失败时，使用港股新目录和美股旧目录，分别标记状态，避免一处失败影响另一市场。

#### 验收清单（本地数据及协议夹具已检查，真实目录待验证）

- 翻页时窗口宽度和位置保持不变；末页不足时保持单只证券宽度并留空，不拉伸。增删自选时重新计算所需总宽，空列表保留添加入口。
- 调整字号不改变单只证券宽度；长名称省略，悬停查看完整名称。

### 全部自选行情

#### 旧版独立窗口（0.6.0 已替换，保留历史说明）

通过悬浮条右键菜单、托盘菜单的“查看全部行情”或设置页同名按钮打开独立窗口。窗口可调整大小，重复打开复用已有窗口。

表格按自选顺序显示名称、代码、最新价、涨跌幅、行情状态及带日期和时区的数据时间。全部自选均列出，不分页，空间不足时滚动；复用已有持续订阅，实时更新。全局展示连接状态，断线保留本次运行的旧价与数据时间。

“管理自选”按钮打开现有设置页；总览页不直接增删或排序。空列表提供添加入口。关闭总览仅关闭该窗口，悬浮条及行情连接继续运行。

- Q2：面板保持只读，提供一个小的“管理自选”入口；添加、删除和排序仍在现有设置页完成。

- Q8：默认贴着横条下方、左侧对齐；下方放不下时改到上方。靠近左右边缘时平移，使面板留在横条所在屏幕的工作区内。上下空间都不足时降低面板高度、内部滚动；工作区宽度不足 320 逻辑像素时，允许突破该最小宽度。
- Q9：沿用横条的深色和字号，使用细边框、小圆角、轻阴影。取消系统标题栏、大标题和底部说明；面板内容区保持不透明，横条透明度设置仍作用于横条。顶部只保留自选数量、连接状态和小型“管理自选”入口。
- Q10：原先确认行悬停详情；2026-10-25 用户改为取消横条和面板的全部行情悬浮详情框（0.6.3）。移动鼠标不再弹出详情，单击行情行不打开新页面。

##### 沿用的行情与管理规则

- 按已保存的自选顺序展示全部证券，复用已有持续订阅和行情状态；打开、收起面板不改变订阅范围，不创建额外的独立总览。
- 正常更新、断线保留本次运行旧价、缺失价格显示 `—`、休市与断线分别表示、延迟和权限标识等沿用既有行情口径；本次改造不据此宣称行情来源或真实权限已通过新增验证。
- 0.6.3 按用户要求移除了行详情与横条悬浮详情的展示入口；行情源时间和报价时段仍在内部数据模型中保留。
- 管理入口仍进入现有设置页；在设置页修改自选后，后续打开面板使用最新列表与顺序。空列表继续提供进入设置添加自选的入口。
- 横条滚轮负责翻页，面板滚轮负责列表滚动。菜单及设置的“查看全部行情”是展开动作，面板已展开时复用；专用箭头才执行展开/收起切换。
- 收起面板不隐藏横条、不停止行情连接；隐藏、全屏、退出等原有生命周期规则继续适用，并增加 Q7、Q12 的面板联动。

本方案只调整全部自选行情的展示与交互。实现使用依附横条的无边框面板窗口，并复用原有行情广播；验证结果按下述验收范围记录，不以旧独立窗口的结果替代新面板验收。

改造前：全部自选均纳入悬浮条，按每页最多 3 只、工作区不足时减少容量的规则滚轮翻页，自选总数上限为 10 只。下述规则替代这些展示及数量限制；自选行情面板继续展示全部自选。

#### 已确认并实现的规则

- Q2：数量设置指“悬浮条每页数量上限”，不限制展示勾选总数。设为 2 时每页最多展示 2 只，更多已选证券继续使用原有滚轮翻页。
- 用户补充：取消应用内自选总数的固定上限，不再限制最多关注 10 只。此决定不代表行情源具有无限请求或订阅能力，来源限制和失败处理需按实际能力处理。
- Q1：在“设置 → 自选管理”的每行增加“显示在悬浮条”勾选框。自选行情面板继续展示全部自选，保持只读，不增加展示选择控件。
- Q3：外观设置名称为“悬浮条每页最多显示”，接受正整数，默认 3，不设置与自选总数绑定的固定上限。工作区放不下时自动减少实际每页数量，剩余通过翻页查看，保持既有单只证券宽度规则。
- Q4：新添加的证券默认不勾选，用户主动选择后才进入悬浮条；移除后重新添加同样按新增处理。旧配置未记录展示选择时，将其中已有自选全部勾选，以保留升级前的展示范围；已经保存的明确空选择不得当成旧配置而重新全选。
- Q5：悬浮条展示顺序由自选列表的拖拽顺序过滤得到，不维护独立顺序，继续仅提供拖拽排序。
- Q6：允许全部取消勾选。已有自选但没有展示证券时，悬浮条显示“请选择展示证券”，保留设置与全部行情入口，不自动勾选证券。真正没有自选时继续提供添加入口。
- Q7：勾选变化立即保存，保存成功后更新悬浮条；每页数量通过现有“保存外观”按钮保存并生效。展示选择与数量设置在重启后保留；保存失败时保留上次成功的设置并明确提示。
- Q8：每页数量上限为 5、只勾选 2 只时，仅使用 2 只证券的展示宽度。多页时末页不足仍留空，窗口宽度和位置不因翻页变化；工作区约束继续按 Q3 处理。
- Q9：勾选、取消勾选、拖拽排序或修改并保存每页数量后回到第一页。普通行情更新保持当前页，不因持续报价跳页。
- Q10：设置页自选管理列表使用内部滚动，保留拖拽排序，显示“共 X 只，悬浮条展示 Y 只”。其中 Y 为全部勾选项数量，不是当前页数量。
- Q11：未勾选的自选证券仍持续更新行情，全部行情面板继续展示所有自选。展示选择仅决定是否进入悬浮条分页，不改变关注关系或行情更新范围。
- Q12：行情服务返回数量或额度限制时，保留全部自选与展示选择，明确显示受影响的行情状态，不静默删除或截断列表。应用保存自选与行情源接受请求是两个独立结果，不将取消应用固定上限描述成无限行情能力。

本次设计分支及完整方案已获最终确认，验收见 [J 组](./acceptance.md)。开发版使用隔离协议夹具和原生 Electron 验证；真实账号的数量或额度限制未实测，不以合成错误测试替代真实服务能力结论。

## 交易时段与报价口径

港股展示常规交易行情；美股展示常规交易、盘前、盘后和夜盘行情。实际权限与数据覆盖需真实账号验证。

| 报价所属时段 | 展示价格 | 涨跌基准价 |
| --- | --- | --- |
| 常规交易 | 对应常规交易最新价 | 上一交易日常规收盘价 |
| 美股盘前 | 盘前最新价 | 上一交易日常规收盘价 |
| 美股盘后 | 盘后最新价 | 当日常规收盘价 |
| 美股夜盘 | 夜盘最新成交价 | 该轮夜盘开始前最近一个交易日的常规收盘价 |

涨跌幅按 `(对应时段最新价 / 涨跌基准价 - 1) × 100%` 展示。缺少可验证基准时显示 `—`；源数据自带的涨跌幅必须核对口径后才能采用。

新时段尚无有效报价时，保留上一支持时段的有效行情，明确显示“待盘前行情”等状态；悬停显示这笔报价的实际时段和时间。取得新时段有效行情后，同时切换价格及其涨跌幅，不能混用两个时段的数据。

同一轮美股夜盘跨越美东午夜时不重置报价或基准；20:00 后的夜盘归属下一自然日，与次日凌晨组成同一轮。使用市场源状态确认是否开市，不根据本地钟点推断节假日开市。休市、缺少夜盘数据或权限时，保留最后有效行情并明确标识。市场当前状态与最后报价所属时段分别记录，避免将旧价标成新时段报价。实现及验证范围见 [夜盘验证](./overnight-validation.md)。

## 数据权限、更新与异常

- 优先实时行情；账号只能取得延迟行情时允许显示，并明确标注“延迟”。
- 无行情权限时标识“无权限”；本次运行已有旧价则保留其价格和数据时间，没有取得过价格则显示 `—`。
- 持续订阅全部自选证券，包含当前页未显示的证券。翻页使用已有数据，不因翻页反复订阅。
- 本程序收到行情更新后，目标在 1 秒内反映到界面；此目标不包含富途或上游数据源的延迟。
- 断线保留本次运行已取得的价格，展示连接状态及数据时间；休市与断线分别标识。
- 断网、OpenD 重启、休眠恢复后，自动尝试重连和恢复订阅；失败时逐步延长重试间隔，避免重复弹窗。需要重新登录时提示用户到官方程序操作。
- 每次启动重新取得行情，启动阶段显示 `—` 和连接状态。旧价格不跨程序启动持久保存。

## 窗口生命周期

- 默认手动启动；开机自启可选，默认关闭。
- 保存并恢复窗口位置及所在显示器；显示器移除或可用区域改变时保证横条可见。
- 所在显示器运行全屏游戏或全屏视频时自动隐藏，退出全屏后恢复；普通最大化窗口仍保持置顶。
- 手动隐藏优先：用户手动隐藏后，退出全屏不能将横条重新弹出，需用户主动恢复。
- 隐藏期间继续接收行情，通过系统托盘恢复；退出才释放本程序的连接和订阅，保持 OpenD 运行。
- 重复启动复用已有实例，避免多个横条和重复连接。

## 技术方案

已确认技术栈为 Electron + React + TypeScript + Vite。具体依赖版本在实现时按兼容性验证结果选定并锁定。

按以下职责组织实现；当前锁定版本的 SDK 已在 Electron 主进程中通过最小真实连接验证，发布包兼容性仍待验证：

| 部分 | 职责 |
| --- | --- |
| Electron 主进程 | 应用生命周期、窗口、托盘、单实例、显示器事件、位置和设置保存 |
| 行情适配器 | OpenD 连接、订阅恢复、权限和市场状态、源数据转换；最小验证已采用主进程运行 |
| preload | 通过 contextBridge 暴露限定动作和数据事件 |
| React 界面 | 悬浮条、自选管理和设置；展示已整理的行情与状态 |
| 行情口径逻辑 | 按证券和交易时段选择价格、基准及状态，便于用固定样本验证跨时段行为 |

不向显示页面暴露任意文件访问、完整 IPC 对象或富途密码；采用 Electron 官方建议的进程隔离。若 SDK 依赖浏览器环境，先验证受控运行方式，再确定最终部署位置，不将主进程可用性视为既定事实。[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)

## 富途接入事实与验证关卡

已确认选择本机 OpenD，登录和验证码在富途官方程序中处理，悬浮条不保存富途密码。

官方 JavaScript SDK 为 futu-api，通过 WebSocket 接入 OpenD。所需地址、WebSocket 端口、SSL 和 key 必须与 OpenD 实际配置匹配；不能直接把 TCP API 的默认端口 11111 当作 WebSocket 端口。官方文档的 Node.js 工具环境和浏览器示例不足以证明 SDK 在 Electron 主进程可直接运行。[SDK 下载与示例](https://openapi.futunn.com/futu-api-doc/quick/demo.html)、[初始化](https://openapi.futunn.com/futu-api-doc/ftapi/init.html)、[OpenD 配置](https://openapi.futunn.com/futu-api-doc/opend/opend-cmd.html)

进入完整界面开发前，需要取得以下实测结论：

1. futu-api 模块入口、运行环境、打包方式及所需 TypeScript 类型适配可行。
2. 本机 OpenD 的 WebSocket 接口可连接，能够验证证券并接收报价推送。
3. 港股、美股、ETF 的实际行情权限、实时/延迟属性和订阅额度可识别。
4. 盘前、盘后字段和收盘价能够满足已确认的涨跌口径；不满足时明确记录缺口。
5. 市场状态与交易日判断可用，能区分休市、待报价、连接和权限状态。

官方报价结构包含盘前/盘后数据，但未明确保证所有字段的跨日计算基准。交易日历未剔除临时休市，应结合市场状态判断。[报价定义](https://openapi.futunn.com/futu-api-doc/quote/quote.html)、[市场状态](https://openapi.futunn.com/futu-api-doc/quote/get-market-state.html)、[交易日历](https://openapi.futunn.com/futu-api-doc/quote/request-trading-days.html)

当前实现使用带独立源时间的 ETH 逐笔确认美股盘前/盘后价格，不直接展示缺少独立时间的基础报价扩展字段。盘后仅使用可确认同日的常规收盘基准；缺失时涨跌幅未知。额外逐笔订阅会占用额度，固定协议样本已通过，真实扩展时段仍待验。见 [ADR 0003](./adr/0003-timestamped-extended-quotes.md)。

上述 1～3、5 已完成开发构建中的部分或全部真实验证，逐项范围见验证记录；发布包、具体数据时延属性和盘前盘后计算基准仍待验证。若接入无法满足已确认需求，先记录实际证据和替代方案，再讨论调整；不静默更换行情来源、技术栈或计算口径。

## 已确认的工程细化规则

以下规则已随完整方案获得用户确认：

- 2026-10-25 显示调整（已实现）：悬浮条、全部行情面板及设置不再展示“时延?”或“时延属性待核验”提示；内部保留未知属性，已确认的延迟行情仍标注“延迟”。隐藏未知提示不代表行情已被核验为实时。
- 连接、市场时段、行情权限/延迟属性分别记录；单只证券长期无成交或价格不变，不直接判为断线。连接或订阅健康无法确认时展示异常/未知状态及已有数据时间。
- 数据时间采用行情对应的源时间；本程序收到数据的时间单独记录，用于更新延迟测量。缺少源时间时显示“数据时间未知”，不以当前时间冒充。
- 时间默认按系统本地时区展示，并保留日期和时区标识；市场时段判断依据所属市场状态和交易日，不写死本地钟点。
- 设置中提供本机 OpenD WebSocket 连接参数。连接 key 与富途账号密码区分处理；如需持久保存 key，采用系统保护方式，不能保护时仅在当前会话保存，不写入明文日志或仓库。
- 初始自选为空，引导添加证券；无效代码、超过 10 只及权限不足均明确提示，保留已有自选和有效数据。
- 后台或隐藏状态限制无用的界面重绘，同时维持必要的订阅和恢复能力；包体积、内存、CPU 占用实测记录，暂不设未经确认的硬指标。

## 交付与持久化

交付 Windows x64 ZIP 包，解压运行，附带所需 Electron 运行时及应用依赖；OpenD 单独安装和运行。第一版不做安装向导或自动更新，采用手动替换程序文件更新。

自选列表、顺序、外观、位置、连接设置与开机自启偏好保存在本地用户数据目录；更新程序不覆盖配置。价格不跨启动保存，富途账号密码不由本程序保存。
