# 0.2.1 恢复与内部更新延迟验收

2026-10-24，Asia/Shanghai。环境为 Windows 11 企业版 10.0.26200、x64、单物理显示器、缩放约 183.75%；Electron 45.0.0、futu-api 10.11.7108；真实 OpenD 返回 serverVer=1011、serverBuildNo=7108。以下区分真实 OpenD、协议夹具和电源事件注入，不能据此把全部产品验收记为通过。

## 发现并修复的问题

1. 单只证券的首次订阅临时失败后，连接保持正常，但该证券永远没有重试。现在在健康检查后补订阅失败的证券，用每连接订阅集合跳过已成功的证券；无权限不循环请求，重连后重新核验。
2. 握手和全局状态成功就清零重试次数，随后立即掉线会始终使用首档间隔。现在只有连接完成并稳定至少 15 秒、再次通过心跳检查后才重置退避；正式间隔仍为 1、2、5、10、30 秒，上限后保持 30 秒。
3. 心跳原先等首次接入流程全部完成后才启动，后续也与快照/逐笔串在同一轮。现在全局健康确认后就启用独立心跳，慢扩展请求不阻塞连接故障检测。
4. 收到 Electron suspend 事件时停止连接、定时重试和在途请求，保留本次行情及源时间；resume 事件立即重连并恢复自选订阅。旧会话回调有代次和取消检查，停止后不再安排过期发布。

最小复现命令为 `node node_modules/vitest/vitest.mjs run tests/quotes.test.ts`。修复前新增的临时订阅失败和短连接退避用例分别超时、得到第二次重试剩余约 122ms（应进入 300ms 档）；修复后通过。另覆盖 10 只自选三轮休眠事件恢复、无响应的半开连接、慢扩展请求期间的心跳、权限恢复及停止后不再重连。

## 真实 OpenD 与应用连接故障

证据为 `artifacts/recovery-live/result.json`，入口为 `powershell.exe -NoProfile -File scripts/check-recovery.ps1 -Live`。这会只读加载真实配置与 Windows 保护密钥，经过应用专属 TCP 转发代理接入本机 OpenD/FTWebSocket，不更改用户配置，不停止 OpenD，不断开主机网络。

2026-10-24 20:35，真实自选 US.SOXL、US.AAPL、US.SPY、HK.00700 重新取价成功；接入前全部显示 `—`。中断本应用连接并拒绝重连约 3.4 秒，旧价及源时间保留，状态未误报已连接；解除阻断后约 5.84 秒完成恢复。之后向实际 Electron powerMonitor 发送 3 轮 suspend/resume 事件，连接在休眠事件后释放、期间不重试，恢复分别约 1.12、1.35、1.23 秒，无连接累积；最终成功恢复 4 个基础订阅。验收启动器也检查进程完成及本轮报告时间，避免读取旧的成功记录。

当时为周六，取得的是源端最后支持时段行情。此项证明真实接入和应用连接恢复，不证明周末产生新成交，不将源时间距现在的差值当作内部更新延迟。密钥和账号资料没有写入报告。

本节是 0.2.1 的应用连接故障与事件注入记录。随后补做了实际 WLAN 断网、OpenD/FTWebSocket 新进程重启及整机睡眠/休眠，三项本机实测通过；操作、系统电源状态、唤醒来源和原始证据见 [真实系统恢复验收](./system-recovery-validation.md)。事件注入本身仍不作为真实系统操作的证明。

## 10 只证券的收到至显示延迟

证据为 `artifacts/recovery-fixture/result.json`、`quotes.png`。入口为先 `npm run build`，再 `npm run test:recovery`。原生集成测试平时跳过，显式入口通过 `STOCK_BAR_NATIVE_CHECK=1` 启用；使用独立测试配置、真实 SDK、正式 preload/IPC/React 及本地协议夹具。

10 只证券每次一起推送，两页各测 10 次；另测隐藏恢复后 5 次、重连后 5 次，共 30 个可见页样本。全部 10 只的接收状态也逐次检查。每个完整连接恰有 10 个唯一基础订阅，翻页不产生新订阅，最终只保留一个活动连接。

测量起点是 SDK 行情回调记录的 `receivedAt`，终点是 MutationObserver 观察到真实价格 DOM 更新后两次 requestAnimationFrame 的时间，包含合并发布、IPC、React 提交与绘制机会；不是只测服务回调，也不包含上游源数据时延。动画帧是绘制机会，不能作为物理屏幕扫描或像素呈现时间的保证。隐藏期间不要求后台绘制，恢复时单独测最新价可见耗时。

2026-10-24 20:28 的原生运行最长 103ms，P95 101ms；隐藏恢复后最新价 DOM 可见耗时 118ms。全部小于 1 秒目标。截图显示第二页 5 只为同一最新推送价格。协议夹具数据明确带 FIXTURE 标记，不作为实盘行情证据。

20:36 对 0.2.1 便携程序再次运行同一验收：30 次测量最长 104ms、P95 100ms，隐藏恢复最新价可见耗时 93ms；三轮电源事件恢复 30/28/31ms（均为夹具，不与真实源接入耗时混同），每连接仍恰好 10 个唯一订阅。发布包证据为 `artifacts/recovery-packaged/result.json` 与 `quotes.png`。
